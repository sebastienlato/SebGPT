### 2026-09-10 — Inspecting a complete pre-norm Transformer block

- **Explanation in our own words:** A Transformer block preserves representation width while combining two different learned branches with two identity routes. Per-position normalization and the `32 -> 128 -> 32` GELU FFN do not mix sequence positions; causal attention is the only cross-position mechanism. Dropout changes branch values only in training mode, and each residual path can preserve both values and gradients when its learned branch is zero.

### 2026-09-10 — Reproducible dropout needs a transaction boundary

- **Explanation in our own words:** A local dropout seed is insufficient if a failed block call can consume only part of its random stream. Both public block entry points must validate both local generators, snapshot both complete current states, treat every later escaping failure as one transaction failure, and restore both streams before re-raising. That includes failure before a draw, between the two dropout sites, after both draws, and while packaging inspection output. Training versus evaluation must also change only dropout behavior; normalization, accepted attention, and FFN arithmetic have no mode-dependent rule.
- **Small example or observation:** If attention dropout draws a mask and the FFN later fails before its dropout draw, retrying without rollback would use a different attention mask. Restoring both streams makes the next successful masks match untouched control blocks. Zeroing the attention output projection keeps the first residual identical across modes, allowing the same normalized and FFN computations to demonstrate that dropout alone owns mode dependence.

### 2026-09-10 — A pre-norm Transformer block composes two learned branches with two identity paths

- **Explanation in our own words:** The accepted Phase 6 block keeps width 32 while applying two different learned branches. First, per-position normalization prepares input for causal four-head attention; dropout acts on that branch output; and the original representation is added back. Second, another independent per-position normalization prepares the first residual for a positionwise `32 -> 128 -> 32` GELU feed-forward transformation; a second dropout acts on that branch; and the first residual is added back. Normalization and the FFN operate within each position, while only accepted causal attention communicates across positions, so the complete composition can preserve causality.
- **Small example or observation:** The topology is `a = x + dropout(attention(norm1(x)))` followed by `y = a + dropout(feed_forward(norm2(a)))`. If an attention or FFN branch is controlled to output zero, its residual result exactly equals the incoming representation, and the identity route can still carry a gradient. Training dropout keeps each activation with probability `0.9` and rescales kept values by `1 / 0.9`; evaluation dropout is identity.
- **What remains unclear:** The conceptual architecture, corrected detailed contract, corrected implementation, and all three exit criteria are accepted. Formal remote closure remains separately gated.
- **Related code, test, decision, or experiment:** DEC-0018; accepted `docs/TRANSFORMER_BLOCK_SPEC.md`; `src/sebgpt/model/transformer_block.py`; `tests/test_transformer_block.py`. The accepted Phase 5 attention remains unchanged. No training, experiment, checkpoint, or sealed-test access occurred.

### 2026-09-10 — Inspecting causal attention without overinterpreting it

- **Explanation in our own words:** A causal attention matrix makes the model's permitted information routing visible. Row `i` describes how output position `i` combines value rows from positions `j <= i`; future entries are exactly zero, visible entries normalize to one, and different heads can distribute weight differently. This is useful internal evidence, but a weight is not a complete explanation: the result also depends on learned Q/K/V projections, value contents, head concatenation, the output projection, and later computations.

Changing only position 2 left earlier single-head and multi-head outputs exactly unchanged; changing position 0 changed the later output by about `16.6667`. Four independently inspected head matrices had shape `(4,3,3)` and different permitted weights while preserving the same causal zero pattern.

### 2026-09-10 — Causal self-attention as controlled information flow

- **Explanation in our own words:** The Phase 4 baseline transforms each position independently, so a prediction cannot use earlier positions even when several positions share one example. Self-attention changes that information boundary. Each position creates a query describing what it seeks, while every position creates a key for matching and a value containing information that may be combined. Query-key dot products become scores, scaling keeps their magnitude suitable for normalization, a causal mask removes future positions, and row-wise softmax turns the remaining scores into weights. The output at one position is the weighted sum of visible value rows. Causality means position `i` may use `j <= i`, including itself, but never `j > i`.
- **Small example or observation:** For three positions, the allowed pattern is `[[yes,no,no], [yes,yes,no], [yes,yes,yes]]`. After softmax, the forbidden entries must be exact zero and every row must sum to approximately one. Changing position 2 cannot change outputs at positions 0 or 1, while changing position 0 can change a later output when the learned projections assign it nonzero weight. Four heads repeat this mechanism with separate learned projections and weight matrices; their width-8 outputs concatenate back to the accepted width 32 before one output projection.
- **What remains unclear:** No Phase 5 conceptual, detailed-contract, implementation, exit, or closure question remains open. Phase 6 architecture is subsequently accepted in DEC-0018; its detailed contract remains a proposal.
- **Related code, test, decision, or experiment:** DEC-0017; accepted `docs/SELF_ATTENTION_SPEC.md`; accepted implementation checkpoint `f4b5a1d8d29ab7ee6eb5b987fe150fb040c4544e`; closure commit `6519d8c813b7e5bc899b73d6b1fa8c38a6819750`. ### 2026-09-09 — Numerical stability includes representability and experiment identity

- **Explanation in our own words:** Subtracting the largest logit prevents naïve exponential overflow, but finite float32 logits do not guarantee that every required difference or final loss is representable in float32. Computing the target margin before adding the small shifted log-sum term avoids an unnecessary large-value reconstruction; the implementation must still detect when the true required float32 result is unrepresentable. Reproducibility also concerns object history, not only seeds: initial measurements, both training passes, and final measurements must use one uninterrupted model and the same parameter objects so reconstruction cannot silently change what the run means.
- **Small example or observation:** With `torch.finfo(torch.float32).max` as the correct target logit and the most-negative finite `torch.finfo(torch.float32).min` as an irrelevant competitor, the competitor's shifted score may become negative infinity while its exponential correctly contributes zero and the loss remains representable. Reversing target and competitor can make the required target margin exceed float32, which should produce a deterministic contract failure rather than accidental infinity. Around evaluation, raw parameter-byte digests distinguish `+0.0` and `-0.0`, whereas numerical equality alone does not.

### 2026-09-09 — Shifted next-token examples and an honest non-attention baseline

- **Explanation in our own words:** Token IDs alone supply no correct answer or error signal. A next-token example pairs each input token with the following token from the same document, so `x = z[s:s+L]` and `y = z[s+1:s+L+1]`. A dataset window says which predictions are grouped together; it does not by itself determine which tokens can influence one prediction. The accepted Phase 4 baseline maps each token-plus-position representation independently to logits, so its effective token context remains one token even when an example contains 64 positions. Softmax turns each row of logits into probabilities, cross-entropy measures the negative log-probability of the correct next token, backpropagation computes gradients, and a separate SGD step changes parameters.
- **Small example or observation:** In a tiny conceptual analogue using length and stride 3, synthetic IDs `[12, 4, 9, 4, 7]` produce input `[12, 4, 9]` with target `[4, 9, 4]`, followed by the one-transition tail `[4] -> [7]`. Phase 4's accepted values are length and stride 64; the smaller numbers only expose the same boundary arithmetic. The boundary token is reused as input to preserve adjacency, but every next-token transition is a target exactly once. Joining the last token of one play to the first token of another would invent a false transition and is forbidden.
- **What remains unclear:** The detailed contract and example/governance slice are accepted and remotely verified. The model/loss/update mechanics are also accepted after Gate 20 focused re-review, while their Gate 21 commit and the bounded experiment remain separately unauthorized.

### 2026-09-08 — Token IDs, learned embeddings, and position

- **Explanation in our own words:** A token ID is only an index into the accepted vocabulary; its integer magnitude contains no amount of meaning and adjacent IDs need not be semantically related. A token embedding table gives each vocabulary row a learnable vector. Direct row lookup is mathematically the same as multiplying a one-hot vector by the table, but avoids constructing the sparse one-hot representation. Position requires a separate representation because token identity says what is present, not where it occurs. SebGPT will add a learned token vector and a learned absolute-position vector of the same width.
- **Small example or observation:** For IDs `[3, 1, 3]`, the same token row is selected twice. Backpropagation therefore adds both position-specific gradient contributions into row 3, while an unrelated row receives zero for that example. In a batch, a position row shared by every member likewise accumulates one contribution per use.

### 2026-09-08 — Token units, vocabularies, and exact round trips

- **Explanation in our own words:** Raw text, token units, vocabulary entries, and token IDs are different layers. Choosing one Python `str` iteration element per token makes the unit a Unicode code point, not a displayed grapheme, UTF-8 byte, word, or subword. The Phase 1 count of 81 distinct training code points becomes the eventual vocabulary size only because we separately chose training-only code-point units and no special tokens. Sorting the integers returned by `ord()` gives a deterministic mapping without making frequency or source order part of token identity.
- **Small example or observation:** In a conceptual input such as `A\nA`, iteration sees three code points. The repeated `A` uses the same ID twice and the newline uses its own ID. Encoding the empty string produces an empty immutable sequence, and decoding it returns the empty string. Exact round trips require preserving every code point and forbid normalization, whitespace cleanup, or unknown-token substitution.

### 2026-09-08 — Code-point mapping and guarded construction in code

- **Explanation in our own words:** The tokenizer's ordered immutable code-point tuple is enough for both directions: a token ID is its tuple index, decoding applies `chr()` to the indexed value, and encoding uses binary search to find `ord(character)`. Because encoding and decoding scan left-to-right, the first invalid unit determines a reproducible failure without returning a partial result. The accepted `Sequence` boundary allows lists, tuples, and other conforming positional containers without coercing generators or unrelated objects.
- **Small example or observation:** A decomposed character such as `e` followed by U+0301 remains two code points, while a precomposed `é` remains one; neither is normalized. Surrogate code points also round-trip through `ord()` and `chr()` in the generic tokenizer even though strict UTF-8 provenance prevents them from appearing in the Shakespeare corpus. At the corpus layer, unioning six per-document sets creates membership without inventing adjacency, and the Shakespeare orchestrator verifies all safe metadata before reading any training text.
